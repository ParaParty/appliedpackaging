# AE2 附属 Mod：包裹自动化系统完整设计稿

## 0. 设计定位

本附属的核心不是增加一个新箱子，也不是做一个通用压缩库存机器，而是给 AE2 自动化体系增加一层 **“包裹化物流”**：

```text
AE2 样板语义 / 相邻存储内容
→ 包裹
→ 包裹路由、过滤、暂存、拆包
→ 目标机器 / 目标网络
```

设计参考两个明确对象：

```text
ME 包裹装配室：
  类 AE2 分子装配室。
  负责样板语义和彩色分包。

ME 打包机：
  类 Create Packager。
  负责相邻存储端点与包裹互转。
```

AE2 的方向型样板供应器只向指定面推送材料，且指定面不提供网络连接，因此适合主网与子网隔离；样板供应器对未配置接口背后的子网也有特殊推入逻辑，可以跳过接口并直接把材料推入子网存储。这个机制是本设计里“样板供应器、装配室、包裹子网”结构的主要依据。

Create Packager 的参考点是：贴相邻库存工作，红石触发时从相邻库存创建包裹；Create 的 Cardboard Package 本身是 9 格临时存储。

## 2. 包裹物品设计

### 2.1 颜色

包裹颜色是 **17 个独立物品**：

```text
Fluix 包裹
白色包裹
橙色包裹
品红包裹
淡蓝包裹
黄色包裹
黄绿包裹
粉色包裹
灰色包裹
淡灰包裹
青色包裹
紫色包裹
蓝色包裹
棕色包裹
绿色包裹
红色包裹
黑色包裹
```

颜色由 `item id` 决定，而不是只写在 NBT / Data Component 里。

优点：

```text
普通管道可以直接按物品过滤颜色。
AE2 过滤器可以直接识别颜色。
JEI / REI / EMI 展示清晰。
和 AE2 彩色线缆的玩家心智接近。
```

### 2.2 不添加空包裹

不添加可获取、可合成、可存储的“空包裹”。

```text
没有空 Fluix 包裹。
没有空红色包裹。
没有空包裹外壳。
```

机器生成的永远是带内容数据的包裹。

技术上 17 个包裹物品 ID 存在，但没有 `PackageData` 的包裹不作为正常玩法物品出现，不进常规创造标签，不进入正常配方链。

### 2.3 包裹允许堆叠

包裹允许堆叠，但只有 **完全相同** 的包裹才能堆叠。

堆叠条件：

```text
颜色相同
marker 相同
contents canonical hash 相同
version 相同
flags 相同
```

一个 `红色包裹 x16` 表示：

```text
16 个完全相同的红色包裹
```

不是：

```text
一个包裹里有 16 倍内容
```

Tooltip 显示应区分：

```text
每包内容
堆叠总计
```

示例：

```text
红色包裹 x16
Marker: 机器框架

每包：
  铁锭 x64
  水 1000 mB

总计：
  铁锭 x1024
  水 16000 mB
```

### 2.4 包裹内容

包裹内容统一使用 AE2 泛型资源：

```java
List<GenericStack>
```

其中每一项是：

```java
AEKey key
long amount
```

不要写死成 `ItemStack` 或 `FluidStack`。AE2 API 中 `MEStorage.insert(AEKey, long, Actionable, ...)` 这类接口本身就是围绕 `AEKey` 做插入与模拟插入，这适合包裹处理任意 AE2 支持资源。

推荐数据：

```java
record PackageData(
    int version,
    List<GenericStack> contents,
    Optional<MarkerSpec> marker,
    String canonicalHash
) {}
```

包裹本身不存：

```text
有序 / 无序模式
```

顺序是打包时的策略，不是包裹属性。

### 2.5 包裹容量

默认容量：

```text
无存储元件：
  9 组
  9 类型
```

ME 打包机可插存储元件扩容：

| 元件   |   组容量 | 类型上限建议 |
| ---- | ----: | -----: |
| 无    |   9 组 |   9 类型 |
| 16k  |  16 组 |  16 类型 |
| 64k  |  64 组 |  63 类型 |
| 256k | 256 组 |  63 类型 |

AE2 存储元件容量是逐级提升的核心组件；用 16k / 64k / 256k 作为打包容量升级，符合 AE2 玩家对存储元件等级的理解。

“组”的建议定义：

```text
物品：
  1 组 = 该物品最大堆叠数量。
  例如铁锭 64，雪球 16，剑 1。

流体：
  1 组 = 1000 mB，数值可配置。

其他 AEKey 类型：
  1 组 = 对应类型默认单位。
```

包裹内部仍然按 `AEKey` 聚合。例如：

```text
铁锭 x4096
```

在 64 组容量下表现为：

```text
1 个 GenericStack
容量消耗 64 组
类型消耗 1
```

## 3. 包裹套包裹：不嵌套，改为再封装

包裹不允许真实嵌套。

包裹内容里不会出现：

```text
红色包裹 x1
```

当 ME 打包机在内容侧遇到包裹，它会把包裹展开，并视为下面三类操作之一：

```text
合并多个包裹
将包裹改颜色 / 改 marker
向已有包裹追加新的内容
```

### 3.1 合并多个包裹

输入存储：

```text
红色包裹：
  铁锭 x64

蓝色包裹：
  铜锭 x64
```

ME 打包机当前颜色设为 Fluix。

输出：

```text
Fluix 包裹：
  铁锭 x64
  铜锭 x64
```

原包裹被消耗。

### 3.2 改颜色

输入：

```text
红色包裹：
  铁锭 x64
```

ME 打包机颜色设为蓝色。

输出：

```text
蓝色包裹：
  铁锭 x64
```

### 3.3 追加内容

输入：

```text
红色包裹：
  铁锭 x64

散装：
  金锭 x64
```

输出：

```text
红色 / 机器设定颜色包裹：
  铁锭 x64
  金锭 x64
```

如果容量不足，操作失败或选择其他可完整处理候选；不允许把一个源包裹拆一半。

### 3.4 marker 合并规则

ME 打包机提供 marker 模式：

```text
保留：
  所有输入包裹 marker 相同则保留。
  marker 冲突则拒绝合并。

覆盖：
  使用机器 ghost marker。

清除：
  输出包裹无 marker。
```

默认推荐：

```text
保留
```

## 4. ME 包裹装配室

### 4.1 定位

ME 包裹装配室是 **包裹版分子装配室**。

它负责：

```text
普通处理样板 → 默认包裹
彩色处理样板 → 多个彩色包裹
包裹样板 → 指定包裹
高级处理样板 → 多个指定包裹
```

它不负责：

```text
相邻存储打包
相邻存储拆包
包裹合并 / 改色 / 追加
主动扫描 ME 网络
主动扫描 ME 接口子网
```

### 4.2 普通处理样板

输入：

```text
A + B + C
```

样板输出：

```text
X
```

装配室行为：

```text
A + B + C → 1 个 Fluix / 默认色包裹
```

AE2 仍然等待：

```text
X
```

包裹只是中间物流，不改变 AE2 对处理样板输出的理解。

### 4.3 彩色处理样板

彩色处理样板是：

```text
普通处理样板 + 输入格颜色元数据
```

普通机器使用它时：

```text
完全等同普通处理样板。
```

ME 包裹装配室使用它时：

```text
按输入格颜色分组，生成多个包裹。
```

示例：

```text
红色输入格：
  A + B

蓝色输入格：
  C + D

样板输出：
  X
```

装配室输出：

```text
红色包裹：
  A + B

蓝色包裹：
  C + D
```

AE2 仍然等待：

```text
X
```

关键实现规则：

```text
颜色跟随样板输入格，不跟随 AEKey。
```

例如：

```text
红色格：铁锭 x1
蓝色格：铁锭 x1
```

输出必须是：

```text
红色包裹：铁锭 x1
蓝色包裹：铁锭 x1
```

不能合并成一个铁锭 x2 包裹。

### 4.4 包裹样板

包裹样板定义一个包裹：

```text
颜色
marker
contents
```

包裹样板的输出就是包裹。

它用于：

```text
装配室本地样板
包裹样板终端组合高级处理样板
```

### 4.5 高级处理样板

高级处理样板由多个包裹样板合成。

它在 AE2 自动合成层面仍然是处理样板：

```text
AE2 inputs = 所有包裹样板内容展平
AE2 outputs = 玩家设置的普通处理输出
```

但 ME 包裹装配室读取它时：

```text
直接按 package plan 生成多个包裹。
```

示例：

```text
高级处理样板：
  红色包裹样板：A + B
  蓝色包裹样板：C + D
  处理输出：X
```

AE2 看到：

```text
输入：A + B + C + D
输出：X
```

装配室输出：

```text
红色包裹 A+B
蓝色包裹 C+D
```

### 4.6 输出口

ME 包裹装配室有本机包裹输出口。

推荐：

```text
9 格输出口
```

包裹生成后进入输出口。

输出口可：

```text
被外部抽取
自动尝试插入相连 AE 网络
```

具体优先级：

```text
1. 输出口先接收生成包裹。
2. 装配室尝试把输出口包裹导入相连 AE 网络。
3. 外部设备也可以抽取输出口。
```

### 4.7 阻挡模式

阻挡模式只在开启时生效。

```text
阻挡模式关闭：
  输出口有包裹也允许继续输入，只要输出口容量足够。

阻挡模式开启：
  只要本机输出口中存在任意包裹，
  装配室拒绝任何新的输入。
```

“新的输入”包括：

```text
样板供应器 pushPattern
外部插入材料
玩家手动放入材料
流体 / 其他 AEKey 输入
```

阻挡模式只检查：

```text
本机输出口
```

不检查：

```text
输出网络
包裹子网
相邻接口
主网库存
```

## 5. ME 打包机

### 5.1 定位

ME 打包机是 **包裹版 Create Packager**。

它负责：

```text
相邻存储端点 ↔ 包裹
```

它只输入 / 输出：

```text
包裹物品本身
```

散装内容不进入打包机本体。

相邻存储端点可以是：

```text
箱子
机器输入口
流体罐
ME Interface 背后的存储子网
其他可识别的 GenericStack 存储端点
```

### 5.2 识别 ME Interface 背后的存储子网

ME 打包机可以把相邻 ME Interface 视为存储端点。

如果该接口背后连接的是存储子网，则打包机识别并扫描这个子网的可用存储。

精确定义：

```text
做：
  打包机扫描相邻存储端点。
  如果相邻端点是 ME Interface，则识别其背后的存储子网。

不做：
  打包机作为 AE 网络设备，直接扫描自己所在任意 ME 网络。
```

这使“主动扫描”变得合理，因为它仍然是：

```text
贴着一个存储端点工作
```

而不是：

```text
无条件读取所在网络库存
```

### 5.3 打包触发

打包机支持主动打包，但必须由明确触发启动：

```text
GUI 按钮：打包一次
红石脉冲：打包一次
红石持续：周期打包，默认关闭或低速
```

触发一次后：

```text
从相邻存储端点生成一个或多个包裹
```

具体数量由容量元件、可用内容、输出口空间决定。

### 5.4 打包容量元件

ME 打包机内部有容量元件槽。

可插：

```text
16k 存储元件
64k 存储元件
256k 存储元件
```

不插元件：

```text
默认 9 组
```

容量表见 2.5。

1k / 4k 是否提供小容量加成属于数值扩展，暂时不定。

### 5.5 打包流程

```text
1. 读取绑定相邻存储端点。
2. 识别散装资源和已有包裹。
3. 已有包裹被展开为内部内容。
4. 应用内容过滤器。
5. 根据容量元件计算可装入内容。
6. 生成目标包裹计划。
7. 模拟从相邻存储端点抽取所有来源内容。
8. 模拟包裹输出口是否能接收输出包裹。
9. 全部成功才提交：
   - 抽取内容 / 消耗源包裹
   - 生成新包裹
   - 放入包裹输出口
```

### 5.6 拆包流程

外部向打包机输入包裹时：

```text
1. 检查是否合法包裹。
2. 检查颜色 / marker / 内容过滤。
3. 展开包裹内容。
4. 模拟完整插入相邻存储端点。
5. 成功才接受包裹。
6. 接受后立即拆入相邻存储端点。
```

如果输入是堆叠包裹：

```text
红色包裹 x16
```

则按单包事务重复处理。

如果目标只能完整接收 5 个包裹：

```text
接受 5 个包裹
返回 11 个包裹
```

但单个包裹永远不会被部分拆开。

## 6. 包裹样板终端，名称待定

建议名称：

```text
ME 包裹样板终端
```

它负责：

```text
编码包裹样板
将多个包裹样板合成为高级处理样板
将高级处理样板拆分为多个包裹样板
```

### 6.1 包裹样板编码

UI 内容：

```text
颜色选择：17 色
marker ghost slot
内容 ghost slots
编码按钮
包裹预览
容量显示
```

输出：

```text
包裹样板
```

### 6.2 多个包裹样板 → 高级处理样板

输入：

```text
多个包裹样板
普通处理输出设置
空白样板
```

输出：

```text
高级处理样板
```

高级处理样板包含：

```text
AE2 inputs：
  所有包裹样板 contents 展平

AE2 outputs：
  玩家设置的普通处理输出

package plan：
  原始包裹样板列表
```

### 6.3 高级处理样板 → 多个包裹样板

输入：

```text
高级处理样板
空白样板若干
```

输出：

```text
多个包裹样板
```

普通处理输出不会写入包裹样板。

UI 应提示：

```text
将拆出 N 个包裹样板。
原处理输出不会写入包裹样板。
```

可选提供：

```text
同时输出普通处理样板副本
```

这个副本保留：

```text
展平输入
原普通输出
```

## 7. 包裹存储总线

### 7.1 定位

包裹存储总线让 AE 网络访问相邻库存中的包裹。

网络看到的是：

```text
包裹物品
```

不是：

```text
包裹内部散装内容
```

它只允许包裹通过。

### 7.2 过滤

过滤范围：

```text
颜色
marker
内容物
```

过滤器只回答：

```text
这个包裹是否匹配？
```

不做：

```text
any / all / exact 模式
```

推荐规则：

```text
颜色过滤：
  匹配选中颜色。

marker 过滤：
  匹配 ghost marker。

内容物过滤：
  包裹内容必须满足过滤槽要求。

三类过滤之间为 AND。
```

---

## 8. 包裹输出总线

### 8.1 定位

包裹输出总线从 AE 网络中输出已有包裹。

它不会把散装物品打成包裹。

如果网络里只有：

```text
铁锭
金锭
水
```

没有包裹，则它不输出。

如果网络里有：

```text
红色包裹
蓝色包裹
Fluix 包裹
```

它按过滤器输出匹配包裹。

### 8.2 过滤

同包裹存储总线：

```text
颜色
marker
内容物
```

## 9. ME 包裹拆包总线

名称待定，但推荐：

```text
ME 包裹拆包总线
```

### 9.1 定位

它等效于：

```text
包裹存储总线仅输入模式
+
直接贴 ME 打包机的拆包逻辑
+
更高效的事务拆包
```

可能配方：

```text
ME 打包机 + 包裹存储总线
```

或：

```text
包裹存储总线 + 成型面板
```

配方待定。

### 9.2 行为

它贴在目标存储上。

AE 网络尝试向它插入包裹时：

```text
1. 检查包裹过滤器。
2. 展开包裹内容。
3. 模拟完整插入目标存储。
4. 成功才接受包裹。
5. 接受后直接把内容插入目标。
```

它只允许包裹通过。

拒绝：

```text
散装物品
流体本体
普通材料
```

### 9.3 与 ME 打包机区别

ME 打包机：

```text
实体物流机器
相邻存储 ↔ 包裹
可打包也可拆包
可插容量元件
```

ME 包裹拆包总线：

```text
AE 总线
只做包裹 → 目标存储
没有打包功能
更高效
更适合自动化子网
```

## 10. 过滤系统统一规则

### 10.1 不做复杂模式

完全砍掉：

```text
any / all / exact 过滤模式
```

过滤器只判断：

```text
这个包裹能不能通过？
```

### 10.2 包裹过滤维度

统一三类：

```text
颜色
marker
内容物
```

### 10.3 内容过滤解释

包裹内容过滤不是“只拆部分内容”。

而是：

```text
如果包裹符合过滤器，则整包通过。
如果不符合，则整包拒绝。
```

拆包永远是整包事务。

## 16. 最终一句话

这个附属的最终结构是：

```text
ME 包裹装配室：
  处理 AE2 样板语义和彩色分包。

ME 打包机：
  处理相邻存储端点与包裹互转，并可识别相邻 ME Interface 背后的存储子网。

包裹：
  17 色独立物品，无空壳，可堆叠，不真实嵌套；
  包裹套包裹被解释为展开后合并、改色或追加。

包裹总线家族：
  只允许包裹通过，负责包裹存储、包裹输出和高效拆包。
```
