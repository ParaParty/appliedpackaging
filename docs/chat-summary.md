我建议名字不要太“工业物流”，而是偏 **AE2 风格的精密封装 / 数据化物流 / Fluix 包裹**。核心感觉应该是：

```text
不是纸箱物流模组
而是 AE2 用 Fluix/石英网络把复杂资源临时封装成“包裹单元”
```

所以整体命名最好围绕：

```text
Package / Parcel / Bundle / Crate
Assembly / Port / Bus / Terminal
Fluix / Encoded / Patterned / Tagged
```

# 4. 整体美术风格

整体风格应该是：

```text
AE2 金属 + Fluix 晶体 + 数据封装感
```

不要做成纯纸箱，也不要太像 Create 的黄铜机械。

更准确地说：

```text
外形可以借 Create Packager 的“包裹物流”直觉
材质必须是 AE2 的石英、Fluix、金属框架、发光线条
```

关键词：

```text
白色石英面板
深灰金属框架
Fluix 紫蓝光
彩色束带
小型封签 / 标签
网格纹理
数据槽
```

避免：

```text
木箱
黄铜齿轮
重工业机械
过多 Create 风黄铜
纯纸板箱
过度花哨的 RGB
```

# AE2 包裹附属 Mod 完整设计

暂定名称：

```text
Applied Packaging
AE2 Packaging
ME Packaging
```

核心玩法一句话：

> **用 AE2 的样板语义生成彩色包裹，用类 Create 打包机处理相邻存储与包裹之间的转换，用包裹总线在 AE 网络中只路由包裹。**

---

# 1. 设计基准

这个 Mod 不是单纯复刻 Create Packager，也不是做一个新的 AE2 存储压缩系统，而是把两套玩法拆开：

```text
ME 包裹装配室：
  类分子装配室。
  负责 AE2 样板语义 → 包裹。

ME 打包机：
  类 Create Packager。
  负责 相邻存储端点 ↔ 包裹。
```

AE2 的样板供应器会把样板输入一次性推入相邻目标，并且材料来自 Crafting CPU 的 Crafting Storage，供应器本身不实际保存这批材料；官方文档也明确说供应器必须一次推出全部输入，不能推出半批。这个 all-or-nothing 语义正适合包裹装配室。([Applied Energistics Guide][1])

AE2 的方向型样板供应器只向指定面推入材料，并且该推入面不提供网络连接，因此可以用来做“主网样板供应器 → 包裹装配室 → 包裹子网”的结构。([Applied Energistics Guide][2])

Create Packager 的核心行为是贴着相邻库存工作，红石触发时从相邻库存创建包裹，且 Create 的包裹默认是 9 格语义；这个正好作为 ME 打包机的玩法参照。([创作Wiki][3])

AE2 的 `AEKey` / `GenericStack` 是本设计的资源基础：`AEKey` 表示物品、流体等资源类型，`GenericStack` 表示某个 key 加数量，因此包裹内容应使用 `List<GenericStack>`，而不是写死 ItemStack 或 FluidStack。([GitHub][4])

# 3. 包裹物品设计

## 3.1 不添加空包裹

不添加玩家可获得的空包裹。

也就是说，不存在：

```text
空 Fluix 包裹
空红色包裹
空包裹外壳
```

机器直接生成带内容的包裹。

技术上仍然注册 17 个包裹物品，但没有 `PackageData` 的包裹视为无效包裹，不进入正常创造标签、不进入配方体系、不作为合法物流对象。

---

## 3.2 包裹允许堆叠

包裹允许堆叠。

堆叠条件：

```text
颜色相同
marker 相同
contents canonical hash 相同
version 相同
flags 相同
```

一个 `红色包裹 x16` 的含义是：

```text
16 个完全相同的红色包裹
```

不是：

```text
1 个包裹里装了 16 倍内容
```

Tooltip 要显示：

```text
每包内容
当前堆叠数量
堆叠总计
```

示例：

```text
红色包裹 x16
Marker: 机械框架

每包：
  铁锭 x64
  水 1000 mB

合计：
  铁锭 x1024
  水 16000 mB
```

---

## 3.3 包裹数据结构

推荐数据：

```java
record PackageData(
    int version,
    List<GenericStack> contents,
    Optional<MarkerSpec> marker,
    String canonicalHash,
    PackageCapacityProfile capacityProfile
) {}
```

颜色不放在主数据里，权威颜色来自物品 ID。

可以保存一个 `color_cache` 用于迁移和校验，但不作为主要判断来源。

---

## 3.4 包裹没有有序 / 无序模式

包裹本身没有：

```text
ordered = true
ordered = false
```

顺序只是在生成包裹时的排序策略。

ME 打包机可以设置：

```text
来源顺序：
  按相邻存储枚举顺序写入包裹。

稳定排序：
  按 AEKeyType、registry id、component / NBT hash 排序。
```

ME 包裹装配室则按样板输入格、颜色组、包裹样板定义来生成。

---

## 3.5 包裹容量

容量以“组”为单位。

默认：

```text
无容量元件：9 组
```

ME 打包机和 ME 包裹装配室都可以插入 AE2 存储元件来提升单个包裹的容量。

推荐初始平衡：

| 容量元件      |  单包容量 | 类型上限建议 |
| --------- | ----: | -----: |
| 无         |   9 组 |   9 类型 |
| 16k 存储元件  |  16 组 |  16 类型 |
| 64k 存储元件  |  64 组 |  63 类型 |
| 256k 存储元件 | 256 组 |  63 类型 |

AE2 原版存储单元有 16k、64k、256k 等容量层级，且物品存储单元在高类型情况下有 63 类型心智；这里借用这个体系作为包裹容量升级非常自然。([Applied Energistics Guide][5])

“组”的换算建议：

```text
物品：
  1 组 = 该物品最大堆叠数。
  铁锭 64 = 1 组。
  雪球 16 = 1 组。
  不可堆叠工具 1 = 1 组。

流体：
  1 组 = 1000 mB。

其他 AEKey 类型：
  默认 1 组 = 该类型注册的默认单位。
  如果附属没有提供单位，则走配置项。
```

包裹内部仍然聚合为 `GenericStack`：

```text
铁锭 x4096
```

在 64 组容量下可以是：

```text
1 个 GenericStack
消耗 64 组容量
占 1 个类型
```

# 4. 包裹套包裹规则

包裹不允许真实嵌套。

也就是说，包裹数据内部不会出现：

```text
contents:
  红色包裹 x1
```

当 ME 打包机在相邻存储中遇到包裹时，包裹会被展开，视为再封装操作。

包裹套包裹等价于三类行为：

```text
合并多个包裹
将包裹改颜色 / 改 marker
向已有包裹追加内容
```

---

## 4.1 合并多个包裹

输入存储中有：

```text
红色包裹：
  铁锭 x64

蓝色包裹：
  铜锭 x64
```

ME 打包机当前颜色设为 Fluix，触发后生成：

```text
Fluix 包裹：
  铁锭 x64
  铜锭 x64
```

原红色包裹和蓝色包裹被消耗。

---

## 4.2 改颜色

输入存储中有：

```text
红色包裹：
  铁锭 x64
```

ME 打包机当前颜色设为蓝色，触发后生成：

```text
蓝色包裹：
  铁锭 x64
```

这不是嵌套，而是重新封包。

---

## 4.3 追加内容

输入存储中有：

```text
红色包裹：
  铁锭 x64

散装：
  金锭 x64
```

打包后可以生成：

```text
红色 / 机器设置颜色包裹：
  铁锭 x64
  金锭 x64
```

如果容量不足，则不执行；不能把一个源包裹拆一半。

---

## 4.4 marker 合并规则

ME 打包机提供三种 marker 模式：

```text
保留：
  如果输入包裹 marker 全部一致，则保留。
  如果 marker 冲突，则拒绝合并。

覆盖：
  使用机器 UI 中的 ghost marker。

清除：
  输出包裹没有 marker。
```

默认推荐：

```text
保留
```

# 5. ME 包裹装配室

## 5.1 定位

ME 包裹装配室是包裹版分子装配室。

它负责：

```text
普通处理样板 → 默认包裹
彩色处理样板 → 多个彩色包裹
包裹样板 → 指定包裹
高级处理样板 → 多个指定包裹
```

它不负责：

```text
相邻存储打包
相邻存储拆包
包裹合并 / 改色 / 追加
Create 式红石打包
识别 ME Interface 子网
```

---

## 5.2 输入来源

ME 包裹装配室支持：

```text
样板供应器 pushPattern
本地包裹样板
本地输入缓存
玩家手动输入
外部管道/接口输入
```

样板供应器模式是核心。

本地包裹样板模式用于“像分子装配室一样直接使用”。

---

## 5.3 普通处理样板

普通处理样板进入包裹装配室时：

```text
样板输入：
  A + B + C

样板输出：
  X

包裹装配室生成：
  Fluix / 默认色包裹：
    A + B + C

AE2 自动合成仍等待：
  X
```

包裹只是中间物流，不是这张普通处理样板的最终产物。

---

## 5.4 彩色处理样板

彩色处理样板是：

```text
普通处理样板 + 输入格颜色元数据
```

普通机器使用它时：

```text
等同普通处理样板
```

ME 包裹装配室使用它时：

```text
按输入格颜色分组生成多个包裹
```

示例：

```text
红色输入格：
  A + B

蓝色输入格：
  C + D

样板输出：
  X
```

装配室生成：

```text
红色包裹：
  A + B

蓝色包裹：
  C + D
```

AE2 仍等待：

```text
X
```

关键实现规则：

```text
颜色跟随样板输入格，不跟随最终 AEKey。
```

例如：

```text
红色格：铁锭 x1
蓝色格：铁锭 x1
```

必须生成：

```text
红色包裹：铁锭 x1
蓝色包裹：铁锭 x1
```

不能因为 key 相同而提前合并。

---

## 5.5 包裹样板

包裹样板定义一个包裹。

数据：

```text
颜色
marker
contents
容量要求
排序 / canonical 规则
```

包裹样板的输出就是包裹。

它可用于：

```text
包裹装配室本地样板
包裹样板终端组合高级处理样板
高级处理样板拆分
```

---

## 5.6 高级处理样板

高级处理样板是：

```text
普通处理样板 + package plan
```

package plan 由多个包裹样板组成。

AE2 看到：

```text
inputs = 所有包裹样板内容展平后的输入
outputs = 玩家设置的普通处理输出
```

ME 包裹装配室看到：

```text
按 package plan 生成多个包裹
```

示例：

```text
高级处理样板：
  红色包裹样板：
    A + B

  蓝色包裹样板：
    C + D

  处理输出：
    X
```

AE2 计算：

```text
消耗 A + B + C + D
等待 X
```

装配室生成：

```text
红色包裹 A+B
蓝色包裹 C+D
```

---

## 5.7 输出口

ME 包裹装配室有一个本机包裹输出口。

推荐容量：

```text
17 格
```

原因：

```text
17 色输入组理论上可能一次生成最多 17 个包裹。
```

输出口行为：

```text
包裹生成后先进入本机输出口。
输出口可被外部抽取。
输出口也可以自动尝试导入装配室连接的 AE 网络。
```

---

## 5.8 阻挡模式

阻挡模式只在开启时生效。

检查对象：

```text
本机包裹输出口
```

不是：

```text
输出 AE 网络
包裹子网
相邻接口
目标机器
```

规则：

```text
阻挡模式关闭：
  输出口有包裹也不阻挡输入，只要输出口容量够。

阻挡模式开启：
  只要输出口中存在任意包裹，
  装配室拒绝任何新的输入。
```

“任何新的输入”包括：

```text
样板供应器 pushPattern
外部插入材料
玩家手动放入材料
流体输入
其他 AEKey 类型输入
```

已有输入缓存中的材料不会被清除，但不会开始新的包裹生成，直到输出口不再滞留包裹。

---

## 5.9 装配室 UI

### 主界面

```text
左侧：
  样板槽
  当前临时样板显示
  容量元件槽

中间：
  输入缓存
  彩色分组预览

右侧：
  17 格包裹输出口

下方：
  默认颜色
  默认 marker
  阻挡模式
  自动导入 AE 网络
  当前状态文本
```

状态文本：

```text

等待输入
输出口阻挡
容量元件不足
输出口已满
输出网络不可用
```

# 6. ME 打包机

## 6.1 定位

ME 打包机是包裹版 Create Packager。

它负责：

```text
相邻存储端点 ↔ 包裹
```

本体只输入 / 输出：

```text
包裹物品
```

散装材料不进入 ME 打包机本体。

散装材料在：

```text
相邻存储端点
```

---

## 6.2 相邻存储端点

ME 打包机贴着一个存储端点工作。

端点可以是：

```text
箱子
机器输入口
流体罐
ME Interface
其他可适配为 GenericStack 存储的端点
```

如果端点是 ME Interface，且它背后连接的是存储子网，则 ME 打包机可以识别该子网并把它当作内容存储。

这不是“打包机扫描自己所在 AE 网络”。

正式定义：

```text
ME 打包机不扫描自身所在网络。
ME 打包机扫描它绑定的相邻存储端点。
如果相邻存储端点是 ME Interface 背后的子网，则扫描该子网存储。
```

---

## 6.3 主动打包

主动打包是正式功能。

触发方式：

```text
GUI 按钮：打包一次
红石脉冲：打包一次
红石持续：周期打包，默认低速或关闭
```

流程：

```text
1. 读取绑定相邻存储端点。
2. 枚举可打包资源。
3. 如果枚举到包裹，展开包裹内容。
4. 应用打包过滤器。
5. 根据容量元件计算可装入内容。
6. 生成目标 PackagePlan。
7. 模拟从相邻存储抽取全部来源内容。
8. 模拟包裹输出槽能否接收结果。
9. 全部成功才提交。
```

---

## 6.4 容量元件

ME 打包机内部有容量元件槽。

可插：

```text
16k 存储元件
64k 存储元件
256k 存储元件
```

默认：

```text
无元件 = 9 组
```

同一台机器每次生成的单个包裹，容量由当前插入的元件决定。

如果输入内容超出容量：

```text
只选择能完整放入的内容
或在严格模式下拒绝打包
```

推荐默认：

```text
选择能完整放入的前若干内容
```

严格模式可作为按钮：

```text
严格整端点打包：
  端点中所有候选内容不能全部放入时，不打包。
```

---

## 6.5 打包输出

ME 打包机有包裹输出槽。

打包成功后：

```text
输出包裹进入本机包裹输出槽
```

默认不做全方向自动推出。

可以被：

```text
漏斗
管道
Create 物流
AE2 导入总线
包裹存储总线
玩家手动
```

取走。

如果后续做自动推出，必须是明确方向，不做全方向随机输出。

---

## 6.6 拆包

外部向 ME 打包机插入包裹时：

```text
1. 检查包裹是否合法。
2. 检查颜色 / marker / 内容过滤。
3. 展开包裹内容。
4. 模拟完整插入绑定相邻存储端点。
5. 完整成功才接受包裹。
6. 接受后立即拆入目标。
```

如果输入是堆叠包裹：

```text
红色包裹 x16
```

按单包事务重复执行。

如果目标只能接收 5 个包裹内容：

```text
接受 5 个
返回剩余 11 个
```

单个包裹永远不会部分拆。

---

## 6.7 ME 打包机不做的事

ME 打包机完全不做：

```text
读取 Pattern Provider
处理 pushPattern
读取普通处理样板
读取彩色处理样板
读取包裹样板
读取高级处理样板
充当包裹装配室
```

模板和样板全部归 ME 包裹装配室。

---

## 6.8 打包机 UI

### 主界面

```text
左侧：
  绑定存储端点状态
  当前识别类型：箱子 / 机器 / 流体罐 / ME Interface 子网
  可打包资源数量

中间：
  打包预览
  包裹展开 / 合并 / 改色 / 追加结果

右侧：
  包裹输入 / 输出槽
  容量元件槽

下方：
  颜色选择
  marker 模式：保留 / 覆盖 / 清除
  排序策略：来源顺序 / 稳定排序
  红石模式
  打包按钮
```

### 过滤页

```text
打包内容过滤：
  决定哪些资源可被打进包裹。

  决定哪些包裹可被拆入相邻存储。
```


```text
包裹数量超过装配室输出口容量
缺少处理输出
缺少空白样板
```

---

## 7.5 拆分 Tab

输入：

```text
高级处理样板
空白样板若干
```

输出：

```text
多个包裹样板
```

可选输出：

```text
普通处理样板副本
```

提示：

```text
高级处理样板的普通处理输出不会写入包裹样板。
```

# 8. 包裹存储总线

## 8.1 定位

包裹存储总线只允许包裹通过。

它让 AE 网络访问相邻库存中的包裹。

网络看到的是：

```text
包裹物品
```

不是：

```text
包裹内部内容
```

它不会把包裹内容伪装成散装库存。

---

## 8.2 过滤

过滤范围：

```text
颜色
marker
内容物
```

三类过滤是 AND：

```text
颜色通过
且 marker 通过
且 内容过滤通过
→ 包裹可见 / 可存取
```

没有设置的过滤组忽略。

不提供：

```text
any / all / exact 模式
```

内容过滤规则推荐：

```text
包裹必须包含过滤槽中列出的内容。
```

反转卡时反转最终结果。

---

# 9. 包裹输出总线

## 9.1 定位

包裹输出总线从 AE 网络中输出已有包裹到相邻库存。

它只输出包裹。

它不会：

```text
把散装物品打成包裹
请求自动合成包裹
拆包
伪装包裹内容
```

如果网络中没有包裹，它不工作。

---

## 9.2 过滤

过滤范围同包裹存储总线：

```text
颜色
marker
内容物
```

适合做：

```text
红色包裹输出到红线
蓝色包裹输出到蓝线
marker = 压印机 的包裹输出到压印机线
```

---

# 10. 包裹拆包总线

推荐名称：

```text
ME 包裹拆包总线
```

---

## 10.1 定位

包裹拆包总线是高效拆包路径。

它等价于：

```text
包裹存储总线，仅输入模式
+
ME 打包机拆包逻辑
```

它贴在目标存储上。

网络向它插入包裹时，它不把包裹作为物品放进目标库存，而是直接展开：

```text
包裹 → 目标存储内容
```

---

## 10.2 行为

```text
1. 网络尝试插入包裹。
2. 总线检查包裹过滤。
3. 展开包裹内容。
4. 模拟完整插入目标存储。
5. 成功才接受包裹。
6. 接受后直接把内容插入目标。
```

它只允许包裹通过。

不允许：

```text
散装物品
普通材料
流体本体
非包裹物品
```

---

## 10.3 UI

```text
左侧：
  包裹过滤
  颜色 / marker / 内容

右侧：
  目标存储状态
  支持资源类型
  最近拒绝原因

底部：
  升级卡槽
```

失败提示：

```text
目标无法完整接收
目标不支持流体
包裹颜色不匹配
marker 不匹配
内容过滤不匹配
```

# 11. 过滤系统总规则


```text

  ↓
```

```text
  ↓

  ↓

  ↓
```

# 14. 正式做 / 暂时不做 / 完全不做

## 14.1 正式做

```text
17 色包裹，颜色独立物品
不添加空包裹
包裹允许堆叠
包裹套包裹 = 展开后合并 / 改色 / 追加
包裹内容用 GenericStack
ME 包裹装配室
ME 打包机
ME 打包机识别相邻 ME Interface 背后的存储子网
ME 打包机容量元件：16k / 64k / 256k
包裹样板
高级处理样板
ME 包裹样板终端
包裹存储总线
包裹输出总线
ME 包裹拆包总线
装配室阻挡模式检查本机输出口
```

---

## 14.2 暂时不做，但以后可以做

这些不影响核心语义，可以作为扩展：

```text
1k / 4k 容量元件是否提供小容量档
MEGA Cells 等附属大容量元件兼容
高级红石模式
加速升级
更复杂的动画
包裹终端批量编辑
更多 marker 策略
多输出口装配室
多包裹并行路由显示
```

---

## 14.3 完全不做

这些正式砍掉，不再作为后续方向：

```text
空包裹
真实包裹嵌套
包裹本身有有序 / 无序模式
ME 打包机读取 Pattern Provider / pushPattern
ME 打包机支持包裹样板
ME 打包机支持高级处理样板
ME 打包机理解彩色样板
ME 包裹装配室执行相邻存储打包
ME 包裹装配室拆包
包裹存储总线把包裹内容伪装成散装库存
包裹输出总线把散装库存自动打成包裹
any / all / exact 过滤模式
装配室阻挡模式扫描整个输出网络
打包机直接扫描自己所在的任意 AE 网络
```

最后一条要特别区分：

```text
不做：
  打包机作为 AE 网络设备扫描自己所在网络。

正式做：
  打包机扫描相邻存储端点；
  如果这个端点是 ME Interface 背后的存储子网，则识别该子网。
```

# 16. 最终一句话定案

> **这个 Mod 的核心是 17 色可堆叠包裹，以及两条互不混淆的生产路径：ME 包裹装配室负责 AE2 样板语义和彩色分包；ME 打包机负责相邻存储端点与包裹互转，并可通过相邻 ME Interface 使用存储子网。包裹总线家族只路由包裹，包裹拆包总线提供高效的包裹到目标存储事务拆包。空包裹、真实嵌套、打包机读样板、总线伪装包裹内容这些方向全部砍掉。**
