# 需求文档

## 1. 项目目标

Applied Packaging / 应用封装是一个 AE2 附属 Mod。它给 AE2 自动化体系增加一层“包裹化物流”：

```text
AE2 样板语义 / 相邻存储内容
-> 包裹
-> 包裹路由、过滤、暂存、拆包
-> 目标机器 / 目标网络
```

这个 Mod 不做通用压缩库存，也不做普通箱子替代品。它只解决一个明确问题：把一批应该被一起移动、过滤、等待或拆入机器的资源封装成一个可路由的包裹单元，并且让这个单元仍然尊重 AE2 的样板、网络、总线和存储心智。

## 2. 目标用户

目标玩家已经熟悉 AE2 自动合成、Pattern Provider、Storage Bus、Export Bus、Interface 子网和存储元件。他们希望把复杂机器输入拆成有颜色和标记的物流包，并通过 AE2 网络或其他物流 Mod 进行路由。

## 3. 核心场景

彩色自动合成：

```text
主网 Pattern Provider
-> ME 包裹装配室
-> 红/蓝/Fluix 等多个包裹
-> 包裹子网或普通物流线
-> 包裹拆包总线 / ME 打包机
-> 目标机器
-> 产物回主网
```

Create 式 ME 子网打包：

```text
ME Interface 子网 / 相邻 AE 设备或线缆
-> ME 打包机
-> 包裹
-> 物流线
-> ME 打包机或包裹拆包总线拆入目标
```

包裹路由与暂存：

```text
AE 网络中已经存在红色包裹、蓝色包裹、带 marker 的包裹
-> 包裹存储总线只暴露包裹物品
-> 包裹卸货总线把匹配包裹完整拆入目标库存
-> 总线绝不把包裹内部内容伪装为散装库存
```

## 4. 功能性需求

R1. Mod 必须注册 17 个独立包裹物品：Fluix 默认色 + 16 个 Minecraft 染料色。颜色由 item id 决定，不仅写入 NBT；物品形态和丢出实体使用同一包裹模型渲染。

R2. 玩家不能正常获得“空包裹”。没有 `PackageData` 的包裹只能作为内部/调试状态存在，不进创造标签，不进正常配方链，不被物流系统接受。

R3. 包裹允许堆叠，但只有颜色、marker、flags 与有序 contents 列表全部完全相同的包裹才能堆叠；内容相同但条目顺序不同的包裹不是同一种包裹。一个 `红色包裹 x16` 表示 16 个相同包裹，而不是一个包裹装了 16 倍内容。

R4. 包裹内容必须以 AE2 泛型资源建模，核心结构是默认有序的 `List<GenericStack>`，其中每项是 `AEKey + amount`。包裹数据层不得合并同类条目或自动排序；同一 AEKey 可以在列表中出现多次。由 sparse 样板生成且需要保留空位的包裹必须额外保存“样板总槽数 + 每个 contents 条目对应的原槽位”布局；布局参与 canonical hash、NBT 身份和堆叠判断，不能从压缩后的 contents 猜测。数据模型和端点适配不能写死成 `ItemStack`；只支持物品的相邻 Forge 端点必须保守拒绝其它 key。

R5. 包裹不允许真实嵌套。当装配输入中出现包裹时，必须在该输入位置展开其有序 contents 后再封装，不得把同类条目合并或把展开内容统一移动到列表末尾；ME 打包机生成包裹时是唯一主动执行确定性内容排序的路径。

R6. ME 包裹装配室的本地样板槽必须接受任意可由 AE2 解码的已编码样板；空白或未编码样板拒绝，无法解码的损坏样板不能解锁输入或开始装配。包裹样板按样板定义生成一个包裹；高级处理样板按输入列颜色一次生成多个有序包裹，marker 固定取处理样板主产物；普通 AE2 crafting / processing / stonecutting / smithing 等样板把所有非空输入槽按编码顺序生成一个默认 Fluix 包裹，并把主输出归一为数量 1 的 marker。样板生成包裹时，包裹内每个条目的顺序、位置边界和数量必须与该样板的非空输入位置完全一致；普通样板、包裹样板以及高级处理样板的每一个输出列都必须把 sparse 空位写入包裹布局，使后续拆包能够恢复原位置。同一 AEKey 出现在多个样板位置时，装配室必须暴露多个独立真实输入槽，生成的包裹也必须保留多个独立有序条目，不得只按总量比较后合并。装配室必须像 AE2 分子装配室一样暴露 Forge item capability：只有安装有效本地样板时才允许外部向匹配位置输入，输入类型和位置由样板严格过滤，外部只允许从有序输出位抽取。高级样板编码格式的 81×81 个 sparse 输入位置必须全部可执行；装配室按原列/原行顺序把非空输入压缩为实际输入槽，但生成各列包裹时必须恢复该列的原行索引。输入槽数量由当前样板决定而不是固定为 6561。GUI 使用 4×4 代理窗口，跳过 sparse 空白；有效输入不超过可见区或后续全为 disabled 槽时不得滚动，只有实际输入超过可见区时才开放对应滚动行。样板过滤只决定真实输入槽的数量、启用状态和可接受内容，不得把过滤物品或过滤数量绘制成槽内物品；空输入槽保持视觉为空，只有真实投入的物品才显示在槽内。Forge item capability 同步暴露当前 N 个输入位与其后的 1 个有序输出位。放入样板后颜色与 marker 以样板元数据或普通样板主输出为权威，不提供可修改的机器槽位或 fallback。本地合成期间真实输入槽必须继续允许玩家交互，材料在进度完成前不得预先扣除；取出任一必需材料时暂停并保留当前进度与计划，补齐后继续，样板本身改变时则取消当前本地计划并把进度重置为 0。只有进度达到 100、输入仍按位置完整匹配且原子扣料全部成功时才允许提交包裹；任一槽扣料失败时不得产出包裹。装配室与 ME 打包机必须共用同一个容量档映射和容量计算规则：容量槽为空时使用 9 单位/9 类型上限，只接受 AE2 16k / 64k / 256k storage component；1k component、完整 storage cell 和 portable cell 均不接受。插入本地样板时必须提前计算其将生成的每一个包裹（高级样板逐列计算）是否适配当前容量；超限样板可以留在样板槽供玩家检查，但 GUI 样板槽必须标红，所有空输入位及外部输入必须锁定，且不得开始装配。Pattern Provider 调用 `pushPattern` 时必须在消耗任一 `KeyCounter` 输入前完成相同的全包裹容量预检，容量不足则整批拒绝且输入保持不变。任何本地或 Pattern Provider 样板路径都不得绕过当前容量档。包裹不允许自定义名称。所有模式仍受合成进度、AE 能量、加速卡和严格有序单包提交约束。装配室阻挡模式默认关闭；开启后，每个新完成批次在自动输出准入时只检查一次所选目标是否已有本批任一包裹物品类型，比较时与 AE2 Pattern Provider 一样忽略 secondary/NBT，目标中的无关物品不得阻挡。准入前还必须逐项模拟目标能否接受所有当前成品；准入成功后必须在同一 server tick 内按队首顺序尽可能清空真实有序输出列表，目标中途拒收时保留剩余成品和批次状态并在后续 tick 继续，不得重新检查阻挡。GUI 或外部 capability 可在批次中途从同一真实队首抽取；列表取空即结束批次，下一完成批次必须重新执行阻挡与整批模拟。ME_NETWORK 直接写装配室自身接入网格的 MEStorage；ADJACENT_BLOCK 不使用机器朝向或背面概念，而是在六个相邻面中选择首个可准入容器，并在该批结束前锁定该方向。装配室必须支持原版比较器，且只输出三个状态：空闲或成品已清空为 0，正在打包为 1，存在未清空的已完成成品为 2；信号不得表示包裹数量，同批完成多个包裹仍为 2。一次成功装配提交算一次打包。开始打包、成功提交成品以及自动输出清空成品时，必须为直连或隔一个红石导体且输入面朝向装配室的原版比较器预约 0-delay 方块计划刻，使比较器逐次采样 `0 -> 1 -> 2 -> 0` 完整周期；不得保存虚拟比较器锁存值，也不得为红石采样延迟物品自动输出。自动输出若清空全部成品，该 server tick 不得启动下一次装配，下一 tick 才允许开始；连续装配时 `0 -> 1` 上升沿数量与状态 2 采样次数都必须等于成功装配提交次数。项目正式发布前不保留旧样板载体、旧 NBT schema 或开发版存档迁移。GUI 的槽位 hover、升级面板、空升级槽图标和容量元件空槽图标必须使用回移的 AE2 当前 main 视觉。

R7. ME 打包机只有水平 `facing` 一个方向状态；底部与模型背面 `facing.getOpposite()` 固定接入同一个 AE2 主节点，其它面不得接入 ME 线缆，不得增加可独立选择的 `network_side` 状态。AE2 扳手按普通可定向 ME 机器规则只旋转 `facing`，模型、动态件、轮廓、背面接线面和右键命中区域随模型一起旋转，底部接线保持不变。只有右键传送带上表面时才允许手动放入输入包裹或取出输出包裹；右键机框、背板、侧面、底面等其它位置一律打开 GUI。机器支持手动/红石触发打包、包裹拆包、源包裹展开后再封装、空容量槽时的 9 单位与 9 类型上限，以及通过 AE2 16k / 64k / 256k storage component 切换对应容量档；容量槽不接受 1k component、完整 storage cell 或 portable cell。同时支持颜色/marker 策略、打包内容过滤、拆包包裹过滤、反转卡内容过滤反转、GUI 工作进度展示和 GUI shift-click 单包输入。marker 过滤必须使用不消耗物品、不随方块掉落的 AE2 fake/config slot，并继续与内容过滤作为两条独立门禁。完成打包后的包裹必须停在去除 4px 后部模块后所得 12x16 前部区域中心，包裹底面位于传送带顶面 `y=2/16`；包裹与帘子的动态渲染只允许位于从工作口向内 15px 的体积，不得进入机器最后 1px 背板，传送带 UV 滚动停止后必须保留当前相位，下一次动画从该相位连续运行。打包机 GUI 的槽位 hover、升级面板、空升级槽和容量元件空槽图标必须使用回移的 AE2 当前 main 视觉；空 marker 槽使用 Applied Packaging 自有 marker 槽图标并提供说明 tooltip。

R8. 包裹样板与高级处理样板统一在 Advanced Pattern Encoding Terminal 中编码；不提供独立 Package Pattern Terminal，也不向 AE2 原版 Pattern Encoding Terminal 增加包裹页面。普通 Pattern Encoding Terminal 的 `ENCODED_PATTERN` 槽必须拒绝 `appliedpackaging:package_pattern` 与 `appliedpackaging:advanced_processing_pattern`，避免接收无法由原版页面编辑的专用载体。高级终端右侧提供高级/包裹两个模式按钮，并在同一个 Screen、同一个 Menu 和同一个已打开容器内切换；当前页由终端 part 持久化，关闭时位于包裹页则下次仍直接打开包裹页。向高级终端的已编码样板槽放入 `advanced_processing_pattern` 或 `package_pattern` 时，必须分别自动切换到高级页或包裹页并载入对应状态；该槽不接受 AE2 原生 crafting/processing/smithing/stonecutting 样板。高级页与包裹页使用完全隔离的输入/输出配置库存：高级页拥有 17x81 个 sparse 输入和 4 个输出，包裹页拥有 81 个 sparse 输入、独立 marker、颜色与自动包裹预览；切换页面不得复制、迁移、清空或复用另一页的输入输出槽。载入包裹样板后的自动输出必须按包裹颜色、输入与 marker 重建，禁止显示相同输入对应的原版合成产物。高级终端不创建任何 `VIEW_CELL` 槽，也不绘制显示元件面板。包裹不提供任何自定义名称入口或名称元数据。所有拾色入口复用同一个纯颜色高层弹窗和同一个触发按钮实现；弹窗以参数决定是否显示 None，只有 Package Storage/Unpacking Bus 的过滤区允许 None，且其颜色按钮右键直接恢复 None。Fluix 与预留的 None 位置固定在最左侧分隔线内上下排列，None 隐藏时仍保留其布局空间，其余 16 色在右侧按 8x2 排列。选中态只替换 8x8 色格背景，不增加外边框或 hover 视觉；弹窗打开时必须拦截触发按钮自身及底层控件的 hover tooltip，不得重复 tooltip、隐藏底层物品或透传输入。

R8 客户端实现约束：高级/包裹页只在 `AdvancedPatternEncodingTermScreen` 内切换，不重新打开 Screen、不替换 Menu、不转移 slot、不委托或覆盖 AE2 原版 `PatternEncodingTermScreen` 的绘制。高级页和包裹页必须使用两套完整布局 profile：高级编辑框为 146px 宽，包裹编辑框保持用户提供的 124x66 原始面板且不允许横向拉伸；两行网络库存时高级页为 217x250（195px 主体加 22px 右侧模式标签区），包裹页为 195x233，相同网络行数下高级页主体比包裹页高 17px。切换时在同一 Screen 实例上重新初始化并重新居中背景、搜索框、网络滚动条、标题、玩家栏、载体槽、编码按钮、模式按钮及当前页槽位，不能只覆盖中间面板。右侧模式按钮必须直接对照 AE2 高版本 Pattern Encoding Terminal 的 `TabButton.Style.HORIZONTAL`：22x22 标签、相邻标签 21px 步进、ItemStack 图标偏移 `(3,3)`，并贴在各自 profile 的编码区右边缘；不得使用右上角外接 `VerticalButtonBar` 或孤立 IconButton。原版 Pattern Encoding Terminal 的 Screen factory、四种原生模式、资源和交互全部保持 AE2 实现；本模组不得通过 ScreenEvent、Screen factory Mixin 或绘制 Mixin 向其加入模式或重画界面。允许的唯一原版终端改动是一个窄菜单槽位验证注入，用于拒绝 `package_pattern` 与 `advanced_processing_pattern`。

R9. 包裹存储总线与包裹卸货总线必须注册为 AE2 cable part，并只处理合法包裹；不再提供 Package Export Bus。两者共用最多 7 行包裹过滤规则，每行由可选模糊开关、可选反转开关、可为空的颜色选择、marker 过滤槽和 6 个普通物品过滤槽组成；颜色空模式表示不按颜色过滤，规则之间按“任一行匹配”处理。默认启用 2 行，每张容量卡额外启用 1 行，最多安装 5 张容量卡并在第 5 张时达到 7 行上限。第一、二行必须对应底图最上方两行，未启用行必须按新版 AE2 可选槽的透明叠加方式显示。模糊/反转按钮只在对应升级卡存在时显示，且无论只显示哪一种，都必须与颜色按钮保持相邻；模糊、反转、颜色三个 8px 按钮统一使用相对 18px 过滤行顶部 2px 的固定上边距，不做垂直居中。空 marker 过滤槽使用 Applied Packaging 自有 marker 槽图标；已解锁空槽 hover 时提供说明 tooltip，锁定行中的图标随槽背景使用相同透明度。包裹存储总线默认优先级为 0，沿用 AE2 当前 main Storage Bus 的 Help、清空、Partition Storage、存储配置工具栏、连接目标提示与升级面板视觉；Partition Storage 必须按相邻容器槽位顺序读取合法包裹，每个不同包裹生成一行颜色、marker 与可完整容纳的内容过滤，忽略散装物品和重复包裹，容器内没有包裹时清空过滤。包裹卸货总线采用 AE2 Formation Plane 式输入端点，默认优先级同样为 0：只接收网络路由来的一个匹配包裹并输出其内容，不扫描或主动抽取其它 ME 存储，也不接受不满足拆包条件的任意包裹作为一般库存；但已经接收且尚未完成拆包的唯一 held 包裹必须作为数量 1 的包裹本身向网络枚举并允许整包抽取，不能暴露其内部散装内容。两个总线的默认值都为 0，玩家通过右上角 Priority 子菜单直接读写该数值，不存在隐藏偏移；数值不同时仍由较高者先接收，数值相同时必须由可接收该包裹的 Package Unpacking Bus 优先，只有拆包总线因 held 忙碌、过滤、阻挡或目标容量拒绝时才继续尝试 Package Storage Bus。其左侧按钮固定为 Help、清空过滤与 AE2 Pattern Provider 同类型的阻挡模式；阻挡开启时，若相邻目标已存在任一包裹内容物类型，则不接收或提交该包裹。卸货总线在同一 5 格升级库存中额外支持最多 4 张加速卡，并显示工作包裹槽和进度条；接收后本地持有包裹并按 0/1/2/3/4 张加速卡对应 20/15/10/6/4 tick 的周期运行，结束时对相邻 item handler 做整包累计模拟，全部可接收且满足阻挡要求后才按包裹 contents 的条目顺序逐条推入。重复 AEKey 条目不得在推入前聚合；当目标是包裹装配室时，目标样板过滤会把这些推送分别落入对应的独立输入槽。当目标是序列缓存器端点时，卸货总线必须走专用原子计划：端点开启样板模式且包裹存在布局时按记录的原槽位保留空位；未开启样板模式或包裹没有布局时按 contents 顺序连续逐格输入，不跳过空位置。目标成员不足、已有锁存、过滤或容量拒绝时不得消费 held 包裹或部分提交。最终检查拒绝时保留原包裹、显示阻塞并定时重新验证；工作、阻塞或空闲期间均允许网络或玩家取回尚未拆完的 held 包裹，取回时必须原子取消工作、清空进度/阻塞/重试状态且不得提交任何内容，拆除 part 时也必须返还。两者右上角均提供与 AE2 当前 main Storage Bus 一致的专用优先级标签入口；卸货总线的工作槽和进度条必须向左避让该入口。两者都不能把包裹内部内容伪装成散装库存，也不能把散装库存自动打成包裹。

R10. 所有整包操作必须先完成所需验证。MEStorage 打包在抽取、输出或容量模拟失败时不得提交；卸货总线在网络插入模拟和最终提交两个阶段都必须重新验证过滤、阻挡与完整目标容量，并采用与 AE2 Pattern Provider 相同的 check-then-push 约定：阻挡模式先检查目标是否已有任一输入类型，再在累计快照中模拟整包内容，全部可插入后才执行真实插入，不额外实现跨第三方 handler 的回滚事务。模拟失败不得写入目标，也不得接收或消耗本地持有包裹。

R11. Tooltip 必须明确显示“每包内容”和“堆叠总计”。高级信息使用 Shift/Ctrl 展示容量、类型数、hash、marker。

R12. 所有玩家可见内容必须有英文与简体中文语言文件。

R13. 必须提供可发布 jar、基础配方、loot table、模型、材质、logo/图标和 mods.toml 元数据；mods.toml 必须声明 Minecraft、Forge、AE2 与 GuideME 发布依赖范围。

R14. 玩家手持包裹并蹲下右键时可以手动拆开手中的整叠同款包裹；掉落实体包裹受到伤害时可以拆开并把内容掉落到世界中。手动拆包不得部分提交；无法转换为普通物品掉落的内容不得销毁包裹。

R15. 加速卡必须缩短设备的实际工作周期，不能只改变空闲扫描或阻塞重试间隔。ME 打包机打包时 0/1/2/3/4/5/6 张加速卡分别使用 40/30/20/15/10/6/4 tick；拆包时只识别前 4 张，0/1/2/3/4 张分别使用 20/15/10/6/4 tick，更多卡仍为 4 tick。包裹卸货总线使用同一拆包速度表并最多接受 4 张加速卡；所有路径最快均为 4 tick。开始一次工作时锁定本次周期长度，保存并同步剩余 tick 与周期总长，GUI 进度按实际周期推进。包裹与传送带的世界动画窗口最长为 20 tick：实际周期超过 20 tick 时只在最后 20 tick 开始移动，20 tick 及以下时覆盖整个实际周期；传送带相位必须按包裹的实际位移同步变化，不能使用独立的固定每 tick 位移。帘子不按工作进度强制播放完整开合周期，而是保存独立的偏转与速度状态；包裹经过时可按实际移动速度施加权重，之后按自身弹性与阻尼回弹，工作结束时来不及回弹就保持当时状态继续自然恢复。ME 包裹装配室继续使用 AE2 分子装配室的加速卡进度表与能量税率。

R16. Mod 必须注册序列缓存器方块。单个缓存器是只保存一种 `AEKey + amount` 的一次输入锁存缓存：一次真实插入成功后立即拒绝任何后续插入，包括同一种 key；模拟插入不得锁存；部分抽取后仍保持锁存，只有数量归零才重新开放。单格容量由服务端配置控制，初始默认 1024，任何路径都不得超过当前容量。物品通过 Forge `IItemHandler`、流体通过 Forge `IFluidHandler`、任意 AEKey 通过 AE2 `MEStorage` 交互；只支持物品或流体的目标必须保守拒绝其它 key。缓存器默认在输入后的下一 tick 才允许主动或被动输出；可配置延迟期间，所属结构内所有缓存器都禁止主动输出和外部抽取。无方向缓存器尝试向除其它序列缓存器外的全部相邻兼容目标自动输出，有方向缓存器可指向上下及四个水平侧，并只向该侧输出；阻挡模式要求对应目标完全为空后才允许提交。

R17. 两个或更多序列缓存器可以沿 X、Y 或 Z 轴组成同一直线多方块。玩家以扳手在未成型端点的任意侧设置指向；对同一侧连续右键时必须按“点击面的对面方向 -> 点击面方向 -> 无方向”三段循环，若前两段触发成型，后续右键仍必须先解散当前结构再继续同一循环。方块更新发现该方向是连续未成型缓存器时，以该方块为唯一端点，并把当时的方向单独记录为端点到尾部的 `sequence_direction`。成型、尾端扩展、拓扑重建与解体都不得改写任一方块原有的 `facing` 或有方向标记；即使原方向与结构轴平行，也只在成型连接模型中隐藏，脱离结构后必须恢复显示原方向。指向路径已经包含其它已成型缓存器时不得再次成型。成型后只允许在尾端同一直线上自动并入新放置方块；新成员复制端点配置，但保留自己已有的方向。拆除端点时整体解散，拆除中段时端点侧连续片段保留，断开后的片段解散并保留最后同步到本地的配置。结构最少 2 格，最大长度由服务端配置控制，默认 128。普通成员的后续扳手调整也使用同一三段循环，成型期间只接受垂直于结构轴的点击面。方块状态必须可区分五种视觉语义：未成型无方向、未成型有方向、端点、已成型无可见输出方向成员、已成型有可见输出方向成员。

R18. 成型结构的端点只充当配置权威和聚合 I/O 端口，失去存储能力，也不属于序列第 1 格；端点指向的第一个成员才是逻辑第 1 格。向端点插入时按第 1 格到尾部顺序选择目标成员；从端点抽取时把全部存储成员按同一顺序暴露为合并容器，端点自身也不执行自动输出。其它成员仍保留自己的单格输入、抽取和自动输出语义。同步模式开启时，所有当前非空存储成员必须在同一次预检中同时满足延迟、阻挡和完整目标容量，任一成员失败则本轮全部不提交。所有设置由端点同步到成员；持久化配置包含自动输出、阻挡、同步、样板、输入延迟和精确 AEKey allowlist，默认值分别为开启、关闭、关闭、关闭、1 tick 和允许全部。

R19. 成型端点必须以专用 `ICraftingMachine.pushPattern` 接收 Pattern Provider 推送，先完成整批规划与容量预检，成功后才一次性消费 `KeyCounter[]`。普通模式仍按已编码样板顺序一格对应一个成员，并在已知 sparse 布局中保留空位置，不把非空输入紧凑前移；第 1 个样板位置只对应逻辑第 1 格。开启样板模式时对已知普通样板执行同一位置映射，并对无法恢复布局的未知 pattern details 严格拒绝；关闭时未知 details 才允许回退到公开执行输入顺序。高级处理样板明确绕过样板模式，只把其公开的实际输入按普通非空顺序逐格分配，不保留 17×81 sparse 空位。结构短于最高目标位置、目标成员已锁存、单格超量或实际输入无法唯一匹配位置时整批拒绝且不得消费输入。

R20. 安装 JEI 时，Advanced Pattern Encoding Terminal 必须为自己的菜单类型注册通用 recipe transfer；不得修改 AE2 原版终端的 JEI 行为，也不得复制任一第三方配方分类。没有专用适配器的配方必须按 JEI 常规槽位协议做通用转换：只消费 `INPUT`，跳过 `CATALYST` 和 `RENDER_ONLY`，只接受可表示为物品或流体的槽位；高级页把全部输入写入一个包裹列并保留最多 4 个确定性输出，包裹页把全部输入写入一个包裹内容表并把第一个确定性物品输出归一为数量 1 的 marker。两页都必须一次性替换各自旧状态、保留当前颜色并由服务端重校验，互不修改另一页数据。输出槽含多个不同候选、概率/区间数量、未知 ingredient type、无确定性输出、容量或 payload 越界时必须在发送前拒绝并显示原因。

Create 专用适配必须保留高级工序语义：序列组装按初始输入和每轮工序的外部消耗顺序展开为多列；动力合成忽略整行/整列为空的分组，在行拆包与列拆包中自动选择包裹数较少的方向，相同时按行，每个非空行或列对应一个有序包裹，并保留该行/列首个材料之前及材料之间的原始空位，不能把材料压缩到第 0 格；其它确定性 ProcessingRecipe 映射为一列。GTCEu 配方必须把一次性 item/fluid content 与每 tick content 乘持续 tick 后映射为一列，并兼容保持 `gtceu` mod id 和现有 recipe capability ABI 的 GregTech Modern - StarT Fork。替代 ingredient 必须与 AE2 15.4.10 样板终端一致，先从终端当前网络库存快照中选择匹配候选，网络候选按可合成、未损坏、现存数量排序；网络没有匹配时再使用玩家物品栏，仍没有时才回退 JEI 当前显示候选或专用配方声明中的第一个可表示候选。物品 Ingredient 还必须允许当前网络中的 NBT/损伤变体通过 `Ingredient.matches` 参与选择；精确数量、最终 AEKey/NBT 和流体数据必须保留。非消耗工具、JEI catalyst 或 chance=0 GTCEu content 不写入输入；机器能量等非资源 capability 不写入样板。Create、GTCEu 与已审查第三方配方中的随机输出、多个序列最终产物、区间数量、动态 NBT、非消耗生成器伪输入或其它无法精确表示的语义必须保守拒绝。任何拒绝、损坏或恶意 payload 都不得部分修改菜单状态。JEI、Create 和 GTCEu 均为可选集成，未安装时不得导致 Applied Packaging 类加载失败，`mods.toml` 不声明硬依赖；其它 Mod 通过 JEI 标准角色协议兼容，不新增硬依赖。

R21. 序列缓存器复用高版本 AE2 ME Chest 的双界面语义。右键成型端点打开主界面，主库存槽按端点后的存储成员数量一一对应并固定显示 3 行 x 9 列；超过 27 个成员时启用按整行滚动的滚动条，不超过 27 个时滚动条禁用但仍必须显示标准 12x15 disabled handle，最后一行及不足 27 个成员产生的越界位置必须渲染为 0.2 alpha 的半透明禁用槽。右键普通成员或未成型单块打开侧面界面，中央唯一存储槽只映射被点击方块本身。主/侧界面都必须通过项目现有 AE2 竖向设置栏提供自动输出、阻挡、同步输出、样板模式和输入延迟五项端点权威设置；输入延迟按 `1/5/10/20/40/100 tick` 预设循环，右键反向循环。允许输入的精确 AEKey 过滤库存仍只预留逻辑和持久化，本版不得恢复已否决的独立 3x3 过滤面板或过滤假槽。1 个升级槽按项目其它可升级机器的现有布局附着在主面板右侧；成型成员界面使用端点权威升级库存。升级槽只接受 1 张红石卡；未安装时自动输出忽略红石，安装后只有端点收到红石信号时整组才允许自动输出。菜单中的物品交互必须继续遵守单次输入锁存、容量、既有过滤配置和输入延迟，流体及其它 AEKey 允许正确显示但不伪装成可由普通物品光标直接搬运的物品。

R22. 本轮高级样板修订覆盖 R6、R8、R19、R20 中旧的“17 列”“通用输入合成一列”描述。高级页逻辑矩阵提高为最多 81 个包裹列、每列最多 81 个材料位置；菜单只同步 4 个可见列窗口，编码 NBT 使用逐列 sparse 数据，AE2 根 `in` 只保存稠密执行输入，并兼容读取现有 version 1 样板。装配室仍以单包容量逐列预检，物理主输出与持久有序队列共同承载超过 17 个结果，不因 GUI 输出槽数量截断样板；每个生成包裹同时从逐列元数据恢复自身 sparse 行布局。

R23. 通用配方导入只维护一套 JEI plugin/transfer handler，不为 EMI 复制第二套实现。JEI 环境直接发现该插件；EMI 环境由 TooManyRecipeViewers（TMRV）把同一个 JEI 插件映射到 EMI，且不需要安装 JEI。JEI、EMI、TMRV 都不写入 `mods.toml` 硬依赖。查看器无关的 `AdvancedPatternTransferPlan` / `PackagePatternTransferPlan`、网络 payload 和服务端校验保持唯一权威。普通确定性 recipe 的每个 item/fluid 消耗槽默认各占一个包裹列；GTCEu 的一次性与 tick item/fluid content 同样一个材料一个包裹；Create 普通 ProcessingRecipe 也逐材料分包。只有明确知道结构的专用适配器可以改变分组：Sequenced Assembly 保留工序列，Mechanical Crafting 在非空行/列中选择包裹数更少的一侧，并把选中行/列的 sparse 位置写入高级计划与网络 payload。

R24. 高级页必须提供转置、移动、自动滚动与颜色模式。转置按钮使用用户更新的 sprite，位于清空按钮正下方，把当前“包裹列 × 材料行”矩阵交换且不丢失输入；产物不转置。空手左键长按已占用输入格 350ms 后进入拾起式移动状态，松手位于另一高级输入格时移动，目标已占用则交换，短按仍保持原 fake-slot 点击语义。用户位于末尾并新增列时，服务端列数同步完成后自动滚到新的末尾。颜色模式仅在高级页存在：默认色为全部 Fluix，循环颜色按包裹列索引循环 17 种 `PackageColor`；切换模式立即重着色现有列，新增列和转置结果继续使用当前模式。

R25. Star Technology 的星门装配在本轮只完成来源与数据结构评审，不进入实现。评审必须先明确它是 KubeJS 注册的 GTCEu `stargate_component_assembly` layered recipe，而不是独立 Java Mod recipe API；现有扁平 GTRecipe 适配不能宣称保留层边界。后续实现应优先读取兼容 GTCEu Fork 的 layered recipe 数据并决定“每层一个包裹”或“层内仍逐材料一个包裹”，不得仅凭 recipe type 名称猜测，也不默认新增泛 KubeJS API。

## 5. 非功能性需求

NF1. 目标平台先固定为 Minecraft 1.20.1 Forge。由于 1.20.1 没有 Data Component，包裹数据使用 ItemStack NBT 保存；业务代码必须通过 `PackageDataStorage` 抽象读写，为未来 1.20.5+ Data Component 适配留接口。

NF2. 公共逻辑必须和 Minecraft/Forge API 解耦到可单元测试的程度。包裹 canonical hash、容量计算、过滤和有序封装计划应能在普通 JVM 测试中验证。

NF3. 客户端渲染、菜单、屏幕、颜色处理必须和服务端逻辑分离，确保 dedicated server 不加载客户端类。

NF4. 行为敏感逻辑必须考虑 GameTest。至少覆盖包裹序列化、MEStorage 打包/拆包、item handler 整包累计模拟、过滤与容量拒绝。

NF5. 资源制作必须保留资产契约、来源和验证记录，避免临时图片无法复现。

NF6. 发布构建不得包含调试物品、临时测试资源、未使用模板包或本地绝对路径。
